Next steps

Where the project stands on 3 November 2026 and what comes next.

The story in five lines

  1. Data is in place. 52 motion families simulated in PhysX, each scene with its counterfactuals, interventions, negatives and measured questions.
  2. One world model, many questions. Forward, backward, property inference and what-if from one network, much faster than the engine.
  3. Two language models on top. A planner that picks actions to reach an outcome, and a reasoner that answers "what if" in plain text; both in training now.
  4. Off-the-shelf models fall short. Language models cannot write dense motion; video models do not move objects plausibly.
  5. Next: train on Dataset V2, test on held-out records, transfer to real rooms through digital twins.

1 · What is done

A simulation dataset built for causal questions

520root scenes
10,011simulated records, first run
7,173 / 774 / 1,287train / validation / test

running A second run is simulating 20,000 more records of the same 52 families into the same dataset (toward about 30,000).

Each root scene is one manifest in a scanned room, simulated in PhysX as a bundle of related runs rather than a single clip. That bundle is what earlier datasets (Physion, MOVi) lack: they show what happens, not what would have happened otherwise.

Counterfactual worlds

The same scene and action with one thing changed: a property (mass, friction, restitution, stiffness), a material, or the shape of the moving object at equal volume and mass.

Interventions and removals

The action changed while the tool is still acting, a late push after an observed prefix, and the removal of a causal link, so the downstream event should disappear.

Variations per root

Up to eight branches per root and several action programs per root, plus an unchanged replay that proves every difference between branches comes from the edit.

Positives and negatives

Action variations that achieve the family's intended outcome and ones that miss it; the misses are kept as labelled negatives, not thrown away.

Questions measured from the simulation

Every record carries timed contact events and question-answer pairs whose answers are read off the saved states, including comparisons across the counterfactual branches (shape, object type, mass, material). No human labels and no language model in the loop.

2 · What we are building

One world model, many questions

The world model reads an object-centric scene (shapes, joints, poses, velocities, properties), a timed action program and any global fields, such as a change of gravity or a wind. During training a mask hides some of it and the network learns to generate what is hidden. Which part is hidden decides the question. Whether the generator is regression, flow matching or diffusion does not change the picture below; those are interchangeable choices inside the block.

The same network, six questions

This is the masked flow-matching model. Each question decides which tokens are known and which are hidden; pick one to see them go through the model.

The simulation is a real PhysX record. The denoising is drawn as the straight path from noise to that record, so it shows the process and is not a model's output: no masked model has been trained on Dataset V2 yet.

Details for each question
  • Forward (fwd): only the motion is hidden. An approximate physics reference (gravity, joints, fields, up to the first unsupported contact) is also supplied.
  • Property inference (prop): mass, friction, restitution and three inertia terms are hidden for every movable object (three are drawn here). Only objects that moved are scored, and the tool never is; static furniture is never hidden.
  • Backward (cause): the action and all motion are hidden, the tool's path too. The final frame enters as a timed token, and the hidden action carries no pointer to its object. Inference samples several candidates and keeps the most consistent; that is not proof of a unique cause.
  • Completion (prefix) and infilling (bridge): the given patches are clamped; their number is drawn at random per example (10, and 10 + 8, in this picture). The physics reference is supplied here too.
  • Unknown properties (unk): the hidden share grows from 30% to 70% over training. Whenever a property or the action is hidden, the physics reference is switched off for the whole scene.

Planned final share of training examples: forward 30%, properties 15%, backward 20%, unknown properties 15%, completion 10%, infilling 10%. Two other masks stay out of training because the answer is not determined: properties and action together from start and end (twice the mass with twice the impulse gives the same motion), and properties from start, action and end alone. Recipe: 8 blocks, width 384, 60 Hz, 0.2 s patches, 10 denoising steps. Code: simagent/unified/wm/masked.py, configs/wm/mechanics_v5/masked_oneshot_prior.json; sample: billiards__r3/a0/factual.

Why learn the simulator (each argued on the Overview and World model tabs)

  • Fast. One network pass predicts the whole horizon instead of thousands of sequential solver steps, and many candidate actions run in one batch.
  • Dense. The output is the full trajectory of every object, so timing questions (a contact before a deadline, time to rest) are checked on it directly.
  • Backward and what-if. Properties and actions inferred from observed motion; interventions and counterfactuals are edits of the conditioning.
  • Physical representation. Metric 3D, object-centric, no camera, so objects persist through occlusion and conservation and non-penetration can be measured and trained.
  • Real scenes. Applies to scene graphs estimated from photographs, with perception uncertainty carried into error bands on the prediction.
  • Rewards for language models. A fast judge for planning and post-training, trusted only as far as it agrees with PhysX.
  • Not limited to what a camera sees. The state can carry quantities that never appear in pixels (below).

Beyond what a camera can see

Physical and chemical processes are not all visible. Charge, current and field strength, temperature, concentration, stress, bond structure or the decay of a radioactive sample leave no trace in an RGB frame, or only an indirect one through whatever an instrument or a renderer chooses to display. A model that predicts pixels can learn only what was rendered, from one camera. A model that predicts a structured state can carry each quantity directly, in its own units, as an attribute of the entity it belongs to.

That is how learned simulators are already built outside rigid-body mechanics: particles and their neighbours for fluids and granular flow (GNS), mesh nodes and edges for cloth, aerodynamics and elastic solids (MeshGraphNets), atoms and their neighbours for interatomic forces in molecular dynamics (MACE), and a multi-scale graph over the globe for weather (GraphCast). Our world model follows the same pattern, with object, joint, action and field tokens. Moving to a new domain means a new schema of entities, relations and fields and new simulation data, not a new kind of model.

Scope. Today the model covers rigid bodies, joints, springs and a few global fields. Processes that change the structure itself, such as a reaction that forms or breaks bonds, a phase change or fracture, need entities and relations that appear and disappear over time; our scheduled removals are the simplest case of that, not a solution. Pixels remain the natural input for perception, since a camera is how a real scene's state gets estimated. The argument is about the space in which dynamics are modelled, not against video models.

Imprecise or missing properties

The world model is told each object's mass, friction and restitution and each spring's stiffness, and a forward prediction is only as good as those numbers. A video model learns the effect of such properties implicitly, from watching objects move, but it cannot be told a value and does not report one. In a real scene precise values are expensive to measure, so the model has to cope with values that are approximate or missing; training can make it robust to that, not guarantee it.

implemented Training with missing values. Some objects' properties are hidden during training while the true trajectory stays the target; the masked model also infers the properties of moving objects from observed motion.
implemented Training with imprecise values (3 November). In a share of training examples the given properties are perturbed as a measurement error would perturb them: one standard deviation is a factor of about 1.6 on mass (with inertia and density moved consistently), 0.15 on friction and restitution, a factor of 1.6 on spring stiffness and damping. The target stays the true trajectory, and the model is told how precise each value is.
planned Evaluation for the paper. The same test records predicted with precise, perturbed (independently per object, or one common mass factor per scene) and partly or fully missing properties, by models trained with and without the corrupted inputs. PhysX re-run with the same wrong values is the reference for how much the true outcome itself changes, reported per family.

3 · What we build on top

A planner and a reasoner, post-trained from Qwen 8B

Planner

Job: given a scene and the outcome an experiment should produce, propose the action (its parameters) that makes it happen.

Stage 1, PhysX: learn from actions whose saved PhysX runs reached the goal, and prefer them over valid actions that missed it (the labelled negatives of Dataset V2).

Stage 2, world model: fine-tune with GRPO and DPO on fresh proposals scored by the world model, which costs a network pass per try instead of a full simulation. PhysX checks that the gain transfers.

Reasoner

Job: like a person shown one simulation and asked "what if the ball were heavier, the domino removed, the push reversed?", say in plain text what would happen, without running the simulator again.

Training: the factual and counterfactual branches of each Dataset V2 root give the question and the measured answer, so every answer is graded against PhysX, not against a human or another model. Supervised fine-tuning first, then GRPO with the measured answer as the reward.

Why: explanations and questions the world model's numeric input cannot express.

trained Planner, PhysX stage: fine-tuned on successful actions, then DPO against the misses; its held-out PhysX evaluation is queued. The world-model stage follows once a world model is trained on Dataset V2.
trained Reasoner, supervised stage: fine-tuned and evaluated against the untrained base model on held-out rooms.
running Reasoner GRPO from the fine-tuned model.

4 · What does not work

Language and video models are not physical simulators

Language models

A dense multi-object trajectory does not fit in an output token budget, so a language model can state an end point but cannot write the motion.

The best route we found is to have the model write code and choose the parameters of an action that should satisfy the task, and let PhysX run it. The strongest closed model does well on simple edits and launches; the open-source Qwen models fail on most of them.

How models are prompted · Results

Video models

Open video diffusion models (Wan2.2, Cosmos-Predict2.5), given the first frame of a PhysX rollout and a prompt, do not produce physically plausible object motion: objects drift, deform, appear or vanish, and contacts do not cause what they should.

They also predict pixels from one camera, so physical state is tangled with appearance and cannot be read off reliably.

What they do have is an implicit sense of how heavy or slippery things are, learned from watching them move; our world model is told those properties instead, which is exact when the values are known and needs the robustness training in Imprecise or missing properties when they are not.

A hypothesis we are not testing ourselves

Why video models may fail, and what this dataset could offer them

A video model learns from RGB pixels alone, with a loss that rewards appearance at least as much as motion. Mass, friction, restitution and the forces acting are never shown to it, and web video rarely shows the same scene twice with one thing changed. So it has little to separate "this looks right" from "this moves right". Others report the same pattern: on controlled physics videos, diffusion video models generalize in distribution but fail out of distribution and appear to imitate the nearest training example rather than learn the rule, and more data and parameters do not close that gap (Kang et al., ICML 2025).

Dense motion and geometry channels

Every record can be replayed into depth, instance masks, motion masks, optical flow and scene flow, exact and aligned with the RGB, because the states are known. Training a video model to predict motion alongside pixels already improves motion coherence (VideoJAM), and depth and segmentation are standard control inputs (Cosmos-Transfer1).

Known causes and counterfactual pairs

These channels show geometry and motion, but not mass or friction; no image channel does. What separates the hidden properties is the counterfactual branch: the same scene and action with one property, shape or field changed, labelled with the value and the timed action. Video models fine-tuned on about 15,000 synthetic force-and-video pairs already learn force and wind controls that generalize (Force Prompting).

We chose the cheaper route: object states and a scene-graph world model, not pixels. The same records could still fine-tune or condition a video model, which makes the dataset useful beyond our own models. This is an argument for the dataset, not a measured result. At tens of thousands of records it is fine-tuning and control scale, not pretraining scale, and the dense channels have so far been rendered for demonstration records only, not for all of Dataset V2.

No off-the-shelf model takes this input (a 3D scene, its properties and an action) and returns this output (a dense 3D trajectory, or the inverse). The comparison for the new world models is therefore PhysX itself as ground truth, a random-action chance rate, our own earlier checkpoints, and the language and video models above.

5 · Next

Plan

  1. Train on Dataset V2. The world models, now with the property, backward and intervention questions, on the 7,173 training records; validation on 774.
  2. Test in distribution. The 1,287 held-out test records: trajectory error in metres, contact and event agreement, and whether the predicted outcome gets the same verdict as PhysX, per question type.
  3. Robustness to measured properties. The same test with precise, perturbed and missing properties in the scene graph, for models trained with and without corrupted inputs, against PhysX re-run with the same wrong values (above).
  4. Counterfactuals from an observation. Let the world model see the factual run when it answers the counterfactual, and score the predicted difference between the two branches on held-out roots.
  5. Transfer to real scenes. Run the trained models on scanned-room digital twins and compare with the real and simulated motion (Digital twins, Twins v2).
  6. Planner and reasoner. Score the PhysX-trained planner on held-out scenes, then adapt it inside the trained world model with GRPO and DPO; finish the reasoner's GRPO. Both scored on held-out roots and audited in PhysX.
  7. Later. Key events first and the motion between them, error bands on predictions, and explanations in words (World model tab, sections 8 and 9).
