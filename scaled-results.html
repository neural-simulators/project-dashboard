Scaled results

Scaled-up data from both code branches: simulated scenes, tasks and actions; open language models compared with GPT-5.4 at writing and checking tasks; learned simulators compared with the physics engine.

The same loop, at scale

The end-to-end study ran at small scale. Here the pipelines of both lines of work are merged and run on close to a thousand simulated scenes from twelve families, including trials converted from the Kubric MOVi and Physion datasets, with over 300,000 PhysX rollouts. The questions: which open models can write tasks or review outcomes in place of GPT-5.4, and which state-predictor architecture, training objective and amount of data predicts motion best.

The ground truth throughout is a physics engine (PhysX, inside NVIDIA Isaac Sim 6.1). After an action, it simulates the scene for 3 seconds; we call one such simulation a rollout. Whether a task succeeded (its verdict) is decided by code that checks the simulated motion. The same code checks the motion predicted by a learned simulator, so every action gets two verdicts we can compare.

Status (14 Oct 2026, 15:13): the test set is fixed (418 tasks). Learned simulators are trained and evaluated; the comparison of LLM reviewers and the action-planning experiments are still running. Sections fill in as runs finish.

Key results

  • Data: 939 simulated scenes (473 kept aside for testing only) and 333,740 three-second physics simulations of actions in them. 89% passed our check that the physics engine behaved sensibly (no objects passing through each other, no energy appearing from nowhere). Scenes come from 12 families, including scenes copied from the public MOVi and Physion datasets.
  • Learned simulators (models that predict how every object moves for 3 s after an action): the best ones predict object positions 0.55-0.57 m off on average over the 3 s, on scenes they never saw. These are the model that predicts the future in one step ('regression') and the model that predicts in a learned summary space ('JEPA'). Models that generate the future by gradually removing noise are worse: flow matching 0.62-0.64 m, diffusion forcing 0.98 m; classic diffusion (DDPM) did not learn.
  • Training choice for flow matching: picking the noise level evenly at random works better than favouring medium noise levels (0.62-0.64 m vs 0.71 m, two runs each), so we use the even choice.
  • What the model needs to know about objects: a detailed description of each object (shape, size, mass, friction, bounciness, how its mass is spread) matters most; a short description makes predictions 0.32 m worse. Randomly rotating and shifting training scenes helps a little (0.05 m). Smaller differences (at most 0.03 m): describing each object by its individual pieces, asking the model to also predict which objects touch, and a 2.5 times larger model.
  • Learning first from the public MOVi and Physion clips, then from our data, lowers the error by 10-14%.

Part 1. Dataset creation

Scenes come from scene generators written in code, from scene descriptions written by GPT, from ReplicaCAD furnished rooms, and from the public MOVi and Physion datasets. Tasks come from fixed rule-based templates (or, for comparison, language models). Actions are chosen by code: random actions, searches around actions that almost worked, and what-if variations (the same action with one setting changed, or with one object removed). The physics engine then simulates every action. Last, who can write tasks and who can check them.

Part 3. Stage 2: action planning

A planner (a language model or a random baseline) chooses an action for each test task, possibly after trying candidates in a learned simulator or seeing what went wrong in the physics engine. Success is always judged by running the chosen action in the physics engine.

Setup

  • Physics engine: NVIDIA Isaac Sim 6.1 (PhysX), 1,920 simulation steps per second, settings that make every run repeatable; each simulation lasts 3 s and is recorded at 30 frames per second.
  • Success of a task is decided by code that checks the recorded motion (no language model involved); the same code checks the motion predicted by a learned simulator, so every action gets a verdict in both.
  • Learned simulators: one transformer network (23 million parameters unless noted); models that generate by removing noise use 50 steps. Validation and test scenes are never used for training.
